\chapter{Funzioni}
\label{chap:funzioni}

\section{Introduzione}
\label{sec:fun-introduzione}
Le funzioni sono blocchi riutilizzabili di codice. In Python si definiscono con \texttt{def}, possono avere parametri, valori di default, \texttt{*args} e \texttt{**kwargs}, e restituiscono valori con \texttt{return}.

Questa descrizione illustra come strutturare funzioni piccole e focalizzate, come documentarle con docstring e come scegliere le firme per rendere il codice facile da testare e riutilizzare. Discuteremo anche gli effetti dello scope e delle chiusure per evitare comportamenti inattesi.

Padroneggiare le funzioni consente di organizzare il progetto in unità logiche, ridurre duplicazioni e migliorare la leggibilità, con impatto diretto su manutenzione e qualità.

\section{Obiettivi di Apprendimento}
\label{sec:fun-obiettivi}
\begin{itemize}
  \item Definire funzioni con parametri e valori di default.
  \item Usare \texttt{*args} e \texttt{**kwargs} per flessibilità negli argomenti.
  \item Comprendere la visibilità delle variabili (LEGB) e le docstring.
\end{itemize}

\section{Concetti Fondamentali}
\label{sec:fun-concetti}
\begin{tcolorbox}[title=Firma delle Funzioni]
Esempio: \texttt{def greet(name: str, upper: bool = False) -> str: ...}

\textbf{Elementi della firma}:
\begin{itemize}
  \item \texttt{def greet}: nome della funzione
  \item \texttt{name: str}: parametro obbligatorio con \textbf{type hint} (annotazione di tipo); indica che `name` dovrebbe essere una stringa
  \item \texttt{upper: bool = False}: parametro opzionale con valore di default e type hint; se non passato, usa `False`
  \item \texttt{-> str}: annotazione del tipo di ritorno; indica che la funzione restituisce una stringa
  \item Type hints sono \textbf{opzionali} e non vincolanti a runtime; servono per documentazione e strumenti di analisi statica (mypy, IDE)
\end{itemize}

Docstring: descrive comportamento, parametri e return.
\end{tcolorbox}

\begin{tcolorbox}[title=Purezza delle Funzioni]
Preferisci funzioni pure (senza I/O al loro interno) quando possibile. Riduci dipendenze globali e I/O nella logica, isolandole in layer dedicati per facilitare test e riuso.
\end{tcolorbox}

\section{Esempi Pratici}
\label{sec:fun-esempi}
\subsection{Funzione semplice}
\label{subsec:fun-semplice}
\begin{lstlisting}
def add(a, b):
    """Ritorna la somma di a e b."""
    return a + b

print(add(2, 3))  # Output: 5
\end{lstlisting}
\begin{tcolorbox}[title=Spiegazione del codice]
\begin{itemize}
  \item \textbf{Definizione}: `def add(a, b)` crea una funzione; il docstring descrive contratto.
  \item \textbf{Return}: restituisce somma di due argomenti; pura, senza I/O.
  \item \textbf{Invocazione}: `print(add(...))` compone I/O con logica; separare in pratica.
\end{itemize}
\end{tcolorbox}

\subsection{Default, *args e **kwargs}
\label{subsec:fun-args-kwargs}
\begin{lstlisting}
def greet(name, upper=False):
    msg = f"Ciao, {name}!"
    return msg.upper() if upper else msg

def total(*args):
    return sum(args)

def describe(**kwargs):
    return ", ".join(f"{k}={v}" for k, v in kwargs.items())

print(greet("Ada", upper=True))  # Output: CIAO, ADA!
print(total(1, 2, 3))  # Output: 6
print(describe(lang="Python", version=3.11))  # Output: lang=Python, version=3.11
\end{lstlisting}
\begin{tcolorbox}[title=Spiegazione del codice]
\begin{itemize}
  \item \textbf{Metodo join}: `", ".join(sequenza)` è un metodo delle stringhe che concatena gli elementi di una sequenza (lista, tupla) usando la stringa come separatore. Esempio: `", ".join(["a", "b", "c"])` produce `"a, b, c"`. Più efficiente di concatenare con `+` in un loop.
  \item \textbf{Default}: `upper=False` definisce parametro opzionale; evita default mutabili.
  \item \textbf{*args} (arguments): il simbolo `*` indica un numero variabile di \textbf{argomenti posizionali} in una tupla. Il nome `args` è solo una convenzione; potresti usare `*numeri` o `*valori`, ma `*args` è lo standard. Permette di passare quanti argomenti vuoi alla funzione.
  \item \textbf{**kwargs} (keyword arguments): il simbolo `**` indica un numero variabile di \textbf{argomenti nominativi} (chiave=valore) in un dizionario. Anche qui `kwargs` è convenzione; `**opzioni` funzionerebbe, ma si usa `**kwargs`. Utile per parametri flessibili con nome.
  \item \textbf{Ordine dei parametri}: quando combinati, l'ordine deve essere: parametri normali $\rightarrow$ `*args` $\rightarrow$ `**kwargs`.
\end{itemize}
\end{tcolorbox}

\subsection{Combinare parametri, *args e **kwargs}
\label{subsec:fun-combinazione}
\begin{lstlisting}
def funzione_completa(a, b, *args, **kwargs):
    """Dimostra l'uso combinato di tutti i tipi di parametri."""
    print(f"Parametri obbligatori: a={a}, b={b}")  # Stampa i valori di a e b
    print(f"Argomenti aggiuntivi (*args): {args}")  # Stampa la tupla args
    print(f"Argomenti nominati (**kwargs): {kwargs}")  # Stampa il dizionario kwargs
    return a + b + sum(args)

# Esempi di chiamata
risultato = funzione_completa(1, 2)
# Output: Parametri obbligatori: a=1, b=2
#         Argomenti aggiuntivi (*args): ()
#         Argomenti nominati (**kwargs): {}

risultato = funzione_completa(1, 2, 3, 4, 5)
# Output: Parametri obbligatori: a=1, b=2
#         Argomenti aggiuntivi (*args): (3, 4, 5)
#         Argomenti nominati (**kwargs): {}

risultato = funzione_completa(1, 2, 3, 4, nome="Test", valore=100)
# Output: Parametri obbligatori: a=1, b=2
#         Argomenti aggiuntivi (*args): (3, 4)
#         Argomenti nominati (**kwargs): {'nome': 'Test', 'valore': 100}
\end{lstlisting}
\begin{tcolorbox}[title=Spiegazione del codice]
\begin{itemize}
  \item \textbf{Ordine rigido}: prima i parametri obbligatori (`a, b`), poi `*args` che cattura tutti gli argomenti posizionali rimanenti, infine `**kwargs` per quelli nominati.
  \item \textbf{*args è una tupla}: puoi iterarla, indicizzarla, usare `sum(args)`, ecc.
  \item \textbf{**kwargs è un dict}: accedi ai valori con `kwargs['chiave']` o `kwargs.get('chiave')`.
\end{itemize}
\end{tcolorbox}

\subsection{Scope e lambda}
\label{subsec:fun-scope-lambda}
\begin{lstlisting}
factor = 2
def mul(x):
    return x * factor  # legge dalla closure globale

double = lambda x: x * 2
print(mul(5), double(5))  # Output: 10 10
\end{lstlisting}
\begin{tcolorbox}[title=Spiegazione del codice]
\begin{itemize}
  \item \textbf{Scope LEGB}: Python risolve i nomi delle variabili seguendo l'ordine LEGB:
  \begin{itemize}
    \item \textbf{L}ocal: scope locale della funzione corrente
    \item \textbf{E}nclosing: scope delle funzioni esterne (closure)
    \item \textbf{G}lobal: scope globale del modulo
    \item \textbf{B}uilt-in: nomi predefiniti di Python (es. `print`, `len`)
  \end{itemize}
  In `mul`, `factor` viene cercato prima in Local (non trovato), poi in Enclosing (non trovato), infine in Global (trovato). Evita dipendenze da variabili globali quando possibile.
  \item \textbf{Lambda}: funzioni anonime per espressioni semplici; preferire `def` per logiche complesse.
  \item \textbf{Effetti}: nessun I/O dentro `mul`; la stampa è separata.
\end{itemize}
\end{tcolorbox}
